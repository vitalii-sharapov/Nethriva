## Install and preserve your library

- Requires macOS 14 or newer; downloadable runtime is Apple silicon/arm64. Generic M1 CPU baseline is checked. Other chips and older supported macOS versions have not all been executed; Intel RDP is not included.
- Choose `Nethriva-0.13.0-macOS-arm64.dmg` or `Nethriva-0.13.0-macOS-arm64.zip`, verify its adjacent SHA-256 file, and confirm About shows **0.13.0 (30)**.
- The app is locally/ad-hoc signed and **not Apple-notarized**. If macOS requires approval, use its normal per-app Privacy & Security process after reviewing the source/download. Do not disable Gatekeeper or remove quarantine to hide a damaged signature.
- Back up your connection library before upgrading. A separately stored Release app still uses the normal existing Release library and Keychain namespace. Saved connection choices are preserved; no user records or credentials ship in the packages. Debug has its own separate profile.
- Download manually from GitHub. Publisher-signed in-app updates remain unavailable until a publisher key is configured; there is no automatic installation.

## Changes since 0.12.1

- Adjustable two-to-four SSH pane groups, adjacent divider resizing, split restoration and detachable sessions. New unrelated sessions open alone.
- Local Terminal, SSH, Telnet, Serial, SFTP and embedded RDP remain available. Structured SFTP adds queueing, progress/cancel/retry/conflict controls and safer staged file publication. SSH workflows add explicit tunnels, jump chains, Quick Connect, bounded remote text editing and reviewed snippets.
- Terminal profiles/search, opt-in private recording, templates/group defaults, previewed bulk editing/migration imports and confirmed multi-session commands.
- Reviewed credential-free shared libraries, external credential-provider integration and authenticated app privacy locking. Lock disconnects sessions and clears temporary authority.
- Virtualization inventories and tabbed VNC/SPICE/WebMKS/RDP consoles for the documented host adapters, with deliberate power/media/snapshot actions. Individual host/provider versions, permissions and identity registration still require live acceptance.
- Hardened import identity/credential authority, SSH reuse, terminal clipboard/prompt handling, SFTP descriptors, console credential submission, RDP trust/defaults and native allocation/cursor ownership.
- Updated runtime/packages: FreeRDP/WinPR 3.33.1, OpenSSL 4.1.0, SwiftTerm 1.99.3, noVNC 1.7.0, reviewed SPICE revision 85262d0, FDK-AAC 3.0.0 and CMake 4.4.5, plus pinned support libraries/tools/actions. Every non-Debug version build checks the complete managed inventory and Xcode before proceeding.
- Fixed SSH's temporary control-socket path overflow on macOS. The fix preserves full authentication/key/forwarding context isolation and reserves OpenSSH's creation suffix.
- Fixed local Xcode RDP loading: normal Run uses optimized Development with local signing/debugger permissions and the existing Release data profile. Production Archive/Profile retain strict Release signing. RDP error details now have readable light/dark contrast and selectable scrollable text.

## Security and compatibility limits

**Known failing hosted check:** on GitHub's macOS 27.0.1 virtual machine, the synthetic encrypted WebMKS console completes its connection/geometry/input checks but its rendered snapshot shows the noVNC background `[40,40,40,255]`, not the required framebuffer color `[32,128,224,255]`. The cause is unresolved; this must not be labeled a harmless test failure or a verified upstream bug. The same console suite passes locally on macOS 27.2 and on the macOS 26 hosted runners. The failing test remains enabled and visible; the current-toolchain build workflow/security acceptance is therefore not green. This release does not claim full macOS 27.0.1 VM-console interoperability. See [the recorded evidence](../../SECURITY_TESTING.md).

The latest Intel macOS 26 job separately failed `testFourNativePanesHaveWorkingDividersAndRestoreAfterRDP`; its WebMKS test passed, and earlier Intel full runs passed. That pane result remains unresolved and visible. The downloadable app/runtime is arm64, not an Intel distribution.

Release status does not constitute production-security approval. Developer ID/notarization, complete current upstream advisory-detail acceptance, broader native fuzzing and the live platform/device/provider matrix remain incomplete. Fourteen assessed findings were verified closed locally; the native dependency baseline is replaced, while its remaining advisory-detail review is open. See [the audit](../../SECURITY_AUDIT.md), [test evidence](../../SECURITY_TESTING.md) and [compatibility matrix](../COMPATIBILITY.md).

Remote CodeQL additionally reports an open High warning for the legacy VMware SHA-1 certificate-thumbprint compatibility path. SHA-256/full-certificate pins are preferred, but this release still accepts a legacy-only ticket fingerprint. This does not concern password hashing; it remains an unresolved certificate-identity hardening item. See [the recorded alert](https://github.com/vitalii-sharapov/Nethriva/security/code-scanning/1). Successful analysis execution is not a zero-findings result.

New RDP defaults require NLA and system certificate/hostname validation, with clipboard/file sharing off. Existing explicitly saved choices remain in place. Review intentional compatibility exceptions before connecting. Telnet and raw TCP consoles do not provide wire confidentiality; SSH forwarding protects its own leg. Never disable trust checks as a generic fix.

Local compilation, synthetic fixtures and generic arm64 headers do not certify M1/M2/M3/M4/M6 execution, older macOS, Intel RDP, live identity providers, full VoiceOver/device support or every server. Existing warnings and remaining scope are retained in the engineering reports.
