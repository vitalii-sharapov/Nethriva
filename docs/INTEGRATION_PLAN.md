# Nethriva integration and packaging notes

Nethriva integrates SwiftTerm for local, SSH, Telnet, and Serial sessions, macOS OpenSSH/SFTP for compatibility with the user's existing configuration, Network.framework for Telnet TCP transport, POSIX termios for local serial adapters, and FreeRDP's native Cocoa client view for RDP. Passwords are stored in Keychain and are not included in the JSON connection store.

Nethriva uses stable persistence and Keychain identifiers so Release application updates continue to find saved connections, groups, and credentials. Xcode Debug builds use separate preferences and a separate Keychain service to keep development records out of the user's Release-profile library and distribution workflow.

Connection libraries can be exported without credentials as `.nethriva` JSON archives or with credentials as password-protected `.nethriva-secure` archives. New credential archives encrypt the complete payload with AES-256-GCM using CommonCrypto PBKDF2-HMAC-SHA256 at 600,000 iterations and a minimum 15 normalized Unicode-scalar password; bounded authenticated older archives remain readable. Imports validate schema and record bounds, preview their contents, preserve empty groups, isolate colliding credential identifiers, and require local per-record approval for sensitive capabilities or existing profile reuse. Archive-controlled UUIDs do not authorize use of existing secrets.

Reusable credential profiles persist only their name, username, and optional RDP domain in a versioned local store with a last-known-good backup. Each profile password uses a separate UUID-keyed Keychain item. Connections may reference a profile UUID; sessions resolve current username/domain when opened and fetch the profile password through Keychain. Password-free archives contain profile metadata and links but no passwords. Encrypted archives may include individual and profile passwords. Old v1 archives without profile fields still decode.

An app-wide Settings scene persists display preferences in the active Debug or Release defaults profile. Sidebar and session headers independently control endpoint and username visibility; usernames are hidden by default. The SSH and Telnet transport banners avoid writing account details into terminal history. Remote-generated terminal text remains under the remote system's control.

Version 0.10.0 adds a complete offline HTML help manual bundled in the application resources. A native SwiftUI help window hosts it through WebKit, with light/dark appearance support, section navigation, full-text highlighting, print styling, a Help-menu command, Command-?, and a main-window toolbar entry.

Version 0.11.0 consolidated Telnet, connection import/export, isolated Debug data, privacy settings, credential and SFTP hardening, and the in-app RDP authentication dialog improvements. Version 0.12.0 adds native Serial sessions, reusable Keychain-backed credential profiles, profile-aware encrypted import/export, Telnet username assistance, and richer sidebar organization. Version 0.12.1 compacts the title, tab, and RDP control bars, and adds confirmed removal of nested groups that relocates their connections to Ungrouped without deleting saved credentials. Source version changes do not by themselves publish a binary GitHub release.

## SSH, Telnet, and SwiftTerm

SwiftTerm 1.99.3 is pinned through Swift Package Manager. Nethriva's `ManagedProcessTerminalView` combines SwiftTerm `TerminalView` with an owned `LocalProcess` adapter for local shells and `/usr/bin/ssh`. SwiftTerm's convenience process view now parses on an internal I/O path, so the app owns delivery to guarantee filtering before parsing. The delivery queue retains at most 1 MiB pending output, applies backpressure without byte loss, preserves termination ordering, and keeps UI callbacks on the main actor. This path supports OpenSSH configuration, key files, ssh-agent, password prompts, and keyboard-interactive authentication. The earlier unused SwiftNIO SSH implementation and packages were removed so there is one supported SSH path.

Every SSH tab now also includes a compact, resizable SFTP tree beside the live terminal. Directory contents load on expansion. Local files and folders can be dropped onto the tree for recursive upload, remote items can be dragged between remote folders to move them, and dragging a remote item to Finder performs a file-promise download. The full SFTP tab remains available for detailed listings and bulk operations. OpenSSH connection multiplexing shares an authenticated transport only between matching identity/security contexts, avoiding repeated authentication during folder navigation. App-owned masters are closed with the last matching tab and during shutdown. Their unpredictable private directory is checked for ownership, permissions and identity; cleanup removes only that owned empty directory, without stale-PID directory deletion. SFTP passwords enter the authentication helper through a private pipe. Automatic submission requires the local SSH-owned PTY's ECHO-off authentication state; remote prompt text alone cannot authorize it. File operations use bounded binary SFTP v3 requests over persistent OpenSSH subsystems, with held no-follow local descriptors and aggregate metadata limits; user paths and listings never pass through a textual command parser.

The actual managed process TerminalView delegate is wrapped to deny remote OSC52 clipboard reads/writes while preserving deliberate Copy/Paste. Local Terminal, SSH, Telnet and Serial ingress also bounds incomplete escape sequences and sixel expansion. Dangerous paste and active application/file links require deliberate review.

Telnet uses a Network.framework TCP connection and a small stateful negotiation layer for echo, suppress-go-ahead, terminal type, and window-size options. The user interface marks Telnet as unencrypted and offers saved-username or saved-password submission only as explicit actions at matching prompts.

Serial uses `/dev/cu.*` discovery and opens the selected local device with POSIX termios, nonblocking reads/writes, and a SwiftTerm tab. Connection records store device path, baud, framing, flow control, and local echo. No username or password is stored for Serial. The connection editor refreshes available adapters while open; an absent adapter produces an error and can be retried after reconnection.

## FreeRDP 3.33.1

FreeRDP is treated as a native dependency and is not reimplemented in Swift. Nethriva includes a self-contained Apple-silicon runtime under `Nethriva/Resources/FreeRDP`, plus a small Cocoa bridge built from FreeRDP's official macOS client sources.

The coherent source-built bundle includes FreeRDP/WinPR 3.33.1, OpenSSL 4.1.0 and linked codec/support libraries. Its source lock, SBOM, provenance, native hashes and provider/bridge checks are enforced by `scripts/check-native-runtime.py`. The recorded downstream patch limits GFX surfaces to 8,192 pixels per dimension, 256 surfaces and 512 MiB aggregate per GFX session. The native set contains 18 binaries targeting generic arm64/M1 and macOS 14; that target is not cross-chip execution certification.

The Swift adapter loads `libNethrivaRDP.dylib` in-process and inserts its `NSView` into the SwiftUI session tab. Credentials are passed directly to the in-process parser and never appear in the operating system's process argument list. OpenSSL provider search configuration is applied through the bridge's own library context rather than mutating the entire app process environment. The tab owns the client context and disconnects it when the tab closes.

New RDP connections require NLA, TLS 1.2 or newer, and macOS system certificate-chain/hostname verification. TLS-only and legacy RDP are explicit compatibility modes, with no silent negotiation fallback. Ignore-certificate or legacy RDP settings require confirmation before credentials are fetched for each session. TOFU requires initial fingerprint approval and refuses changed pins. A validated private per-profile certificate directory is supplied before startup. Direct connections suppress the pre-TLS username cookie; gateway/load-balancing routing remains a documented exception.

The server authentication alert offers an unchecked **Save credentials in Keychain** option. The native view retains that candidate only within its session, and the Swift adapter consumes it only after FreeRDP reports a connected desktop. The app then updates the saved connection's username/domain and writes its password to the matching Debug or Release Keychain service. Failed, cancelled, gateway, and smart-card authentication does not save credentials.

The embedded surface measures its actual detail-area bounds in logical macOS points. It uses those measurements for the initial desktop size and sends debounced Display Control monitor-layout updates after app-window or sidebar resizing. Local drawing and pointer mapping scale continuously while the server applies a new resolution.

The connection editor exposes dynamic resolution, scaling, network profile, H.264/AVC444, clipboard, audio input/output, home/custom folder redirection, printers, smart cards, USB, domain, RD Gateway, certificate policy, administrative sessions, and reconnect limits. Clipboard/file sharing and sensitive device redirects are opt-in; existing explicit saved settings remain intact. The Cocoa bridge translates macOS editing shortcuts into Windows control shortcuts and exchanges bounded clipboard text as UTF-16LE `CF_UNICODETEXT`, with local clipboard actions gated to the visible focused RDP pane. Finder drops and copied Finder items use the RDP file-clipboard protocol: Nethriva activates the remote drop point, advertises file descriptors, streams file contents on demand, waits for Windows to acknowledge the new clipboard offer, and issues a Windows paste without first copying the item into a local staging directory.

The bundled runtime includes its linked third-party license texts. Production distribution still requires approved Developer ID signing, Hardened Runtime without developer exceptions, notarization and a stapled ticket; ad-hoc test builds do not satisfy that gate. Intel RDP needs a separately built and validated native runtime.

References: [FreeRDP repository](https://github.com/FreeRDP/FreeRDP) and [official compilation guidance](https://github.com/FreeRDP/FreeRDP/wiki/Compilation).

## VM integration architecture (0.13.0)

`VirtualizationConfiguration` extends saved connections with optional, backward-compatible host/platform/console settings. `VirtualizationHostView` owns an inventory adapter; each `VMConsoleSessionView` owns its console descriptor and transport independently. Unsaved host credentials are scoped to open tabs in `AppState`; only explicit saves reach Keychain.

`VirtualizationHTTP` supplies ephemeral per-host HTTP/WebSocket sessions, bounded responses, safe authentication errors, strict/default TLS, optional TOFU fingerprints, and bounded XML parsing without DTD/entity expansion. `RESTVirtualizationBackend` handles Proxmox REST, Xen Orchestra JSON-RPC, and Nutanix REST. `VMwareBackend` uses vSphere SOAP. `SSHVirtualizationBackend` uses host virsh or encoded Hyper-V PowerShell through OpenSSH, with passwords delivered by private pipe.

`VMConsoleTransport` bridges native TCP/WSS to bundled noVNC/SPICE modules through a private WebKit message handler. JavaScript cannot select a new native endpoint: channels use the Swift-owned descriptor. The console scheme handler serves only bundled files; embedded web storage is nonpersistent. Direct TCP consoles may use an owned loopback SSH forward. VMware obtains `AcquireTicket(webmks)` and uses noVNC's standard RFB/VMware-cursor support without modifying upstream modules or distributing a proprietary SDK; Hyper-V reuses embedded FreeRDP with a validated VM GUID.

Direct unprotected TCP VNC/SPICE never automatically fetches or submits saved/provider passwords. A manual unsaved password requires one-session plaintext approval. Verified TLS/WSS or a suitable SSH tunnel is preferred; SSH encryption covers its own leg and cannot secure a separate unencrypted final hop.

VMware WSS uses an isolated transport with no API cookies or HTTP credentials, no redirects, and binary WebSocket subprotocol. The API-issued certificate identity authorizes only the ticket's exact host/port: prefer SHA-256 or a PEM certificate, support legacy SHA-1 where provided, otherwise require system trust. A mismatched pin never falls back to weaker trust or the parent API's ignore-certificate policy. One native channel consumes each ticket; reconnect obtains another. Ticket URLs are never passed to JavaScript, storage, exports, or error text. Interactive federated API login now has an experimental registered-client flow; console opening itself does not navigate through vCenter/ADFS.

The optional ticket hash-algorithm field may be inferred only from a strictly validated SHA-1/SHA-256 digest when omitted. VMware ticket channels use `VMConsoleTicketTLS` with Network.framework TLS/WebSocket, a TLS 1.2 minimum, binary messages, automatic ping replies, and an 8 MiB inbound message limit. Its verify callback is installed before protocol options are copied into a connection; a matching ticket pin authorizes that exact certificate, while a missing pin requires system chain/validity/hostname verification. No global ATS exception is introduced. HTTP API and other WebSocket paths remain on URLSession. Per-ticket trust outcomes are lock-protected, and errors expose only numeric TLS/network codes, never raw endpoint-bearing errors. Synthetic tests cover hostname-based legacy/omitted-algorithm acceptance, mismatch/missing-pin rejection, blocked redirects, header isolation, framebuffer/cursor rendering, and Ctrl+Alt+Del.

Ticket URL parsing follows VMware's URL precedence for WebSocket tickets, rather than requiring redundant host/port metadata to match. Without a URL, endpoint fallback is restricted to the same API origin after `about.apiType == HostAgent`; vCenter targets are never guessed. Validation failures name only fixed field labels. Regression checks cover differing URL metadata, omitted standalone endpoints, vCenter rejection, secret redaction, and the complete pinned console rendering/input path.

Upstream console modules remain unmodified and separately replaceable. Retain their source and license notices in every binary; see `THIRD_PARTY_NOTICES.md` and the bundled `Consoles/DEPENDENCIES.md`. The Nethriva wrapper handles keyboard controls, fitting, guest-agent resizing, opt-in clipboard, and socket ownership.

The wrapper hides the SPICE host by default and shows it only for SPICE sessions. noVNC appends its own full-height container to the outer screen; leaving the SPICE placeholder visible pushes that canvas below the viewport. Regression coverage must assert visible canvas geometry and renderer-host exclusivity in addition to pixel decoding. The visibility test failed before the fix and passes afterward; upstream renderer code is unchanged.

VNC/SPICE/VMware tabs expose a visible **Fit Screen** button. It enables and reapplies local scaling even if fit was already enabled. Local auto-fit and optional guest resizing use separate session state/actions; guest resizing defaults off and requires server/agent support outside view-only mode. Fitting is available in view-only sessions and never reconnects or changes credentials. Tests cover repeated action delivery and shrinking the encrypted console viewport while preserving aspect ratio and framebuffer dimensions.

Implementation and automated checks are present, but live host interoperability remains pending. Nutanix console access requires the newer console-token API plus accepted WSS authentication; VMware direct WebMKS behavior must be validated on actual host versions, and the Mac needs access to the ESXi console endpoint, not only vCenter. See [VIRTUALIZATION.md](VIRTUALIZATION.md) for the supported paths and limits. Media actions attach existing host media, never install packages in the guest or upload a Mac file automatically.

## Advanced integration — original roadmap 24–30

`VMAdvanced.swift` supplies bounded guest address/resource parsing, credential-free guest shortcuts, snapshot naming, X11 configuration, session keyboard ordering, architecture-aware RDP bundle roots and memory-only VMware federation. `ASWebAuthenticationSession` handles registered native-client MFA; S256/state/callback checks precede bounded HTTPS token requests and vCenter 7.0.2+ token exchange. The original SAML bearer XML goes into a SOAP WS-Security header for `LoginByToken`, not a password login. Lock/quit/last-related-tab close/deletion clear authorization. No IdP reconfiguration, client secret, bearer archive, insecure fallback or automated Keychain access was added.

The backend protocol exposes optional snapshot/detail capabilities and task progress. VMware uses existing SOAP properties/tasks; Proxmox uses configuration/agent/snapshot endpoints; SSH adapters use quoted virsh and encoded Hyper-V checkpoint commands. Mutations retain explicit confirmation and stale-snapshot membership validation. Stop Monitoring cancels local observation, not accepted host work; no replay. Unsupported adapter snapshots are disabled. Native outer-TLS console transport uses TLS 1.2+ and system hostname/chain trust; it is not VeNCrypt negotiation. X11 is terminal-only, explicit and non-multiplexed; SFTP disables X11.

`VerifiedUpdates.swift` accepts only newer stable releases, a publisher-key-signed bounded manifest and repository-scoped HTTPS asset URLs, matching architecture and exact ZIP hash/size. There is no pinned publisher key in current source, so verified downloads fail closed. The publisher script explicitly creates/signs with a private key outside normal builds; no key generation/publication was performed by the agent. Installation/Gatekeeper approval stay manual. Release packaging uses temporary invocation-owned output, refuses overwrite, validates native runtime layout/slices/dependencies and requires an independently built Intel FreeRDP bundle for universal releases. CI cross-builds the core; this does not certify Intel RDP.

Session keyboard selection raises existing detached windows rather than recreating sessions. The sidebar handles focused selection, group expansion and type-to-search; accessibility actions preserve username/privacy presentation. Auxiliary SwiftUI content is wrapped once in a plain native sibling container before shielding, preventing unsupported NSHostingView subview insertion. See [ADVANCED_CONNECTIONS.md](ADVANCED_CONNECTIONS.md) for user setup and remaining live acceptance.

## Reliability integration

File operations now use `StructuredSFTP.swift`: bounded SFTP v3 messages over an OpenSSH subsystem, persistent browse channels, separate transfer workers, eight-request pipelining, atomic regular-file staging, and safe conflict handling. The authentication bootstrap uses command-free system SSH (`-T -N -f`) to create/reuse the app-owned master with private-pipe passwords; it does not rely on `sftp` creating a master, which recent OpenSSH versions disable. User paths never enter expect's command channel and directory output is not parsed. Upload attempts refresh local resource metadata at both boundaries to avoid stale queued URLs and detect source changes before publish. `SFTPTransferQueue` owns ephemeral jobs and explicit retry decisions. Symlinks/special files are not followed; safe overwrite requires the POSIX-rename extension and folder merges are non-transactional.

`SessionRecovery` observes sleep/network changes once per application and debounces availability. Reconnection is opt-in and does not replay commands, transfers, or VM actions. `SessionFocusGate` plus per-tab environment state prevents inactive surfaces from requesting focus. Inventory parsing/sorting/search run through background work. Connection Check has bounded non-authenticating probes plus an explicit SSH/SFTP login action and fixed, redacted report fields.

Hosted XCTest now uses a per-process preferences/credential namespace with no personal/legacy fallback. The configured macOS 14/15/26 CI matrix still needs a published push/run; exact remote server compatibility remains an acceptance task. See [RELIABILITY.md](RELIABILITY.md) for safety limits and tests.

## Workflow integration

`SessionSurfaceStore` retains one native hosting controller/view and explicit resource lifetime per tab. SwiftUI `SessionMount` markers report viewport geometry; the live hosts are siblings of the shell in a plain AppKit content container, not descendants of another SwiftUI hosting graph. This boundary is important: nesting and migrating hosting graphs rebuilt native surfaces in a failing regression. Tests cover repeated detach/dock, native creation/destruction counts, split geometry and inactive visibility. A single main workspace prevents multiple windows claiming the same live view. `SessionLayout` keeps split membership and weights separate from the selected tab, so new sessions open alone and returning to a split member restores its group. An SSH-only group supports up to four terminal panes through explicit Add to SSH Split. Twelve-point native divider handles capture window-coordinate drag deltas and original geometry, resizing only adjacent panes; double-click equalizes sizes. Divider movement updates markers without replacing hosting roots. Hidden group members keep their split frames and split-mode environment while another tab is shown alone, avoiding background terminal viewport changes. The separate SSH tree hides in any multi-pane split. Window close docks a detached session; tab close ends it.

`WorkflowLibrary` stores bounded versioned snippet/tunnel definitions in the active local preferences profile and preserves corrupt data. `TunnelManager` leases existing authenticated app-owned OpenSSH masters, resolves their private socket with bounded `ssh -G`, and issues isolated `-F none -S … -O check/forward/cancel` requests. App-owned masters clear inherited config forwards to prevent ownership ambiguity. Listeners default to loopback; no automatic replay. Ordered jump editing maintains the existing persisted `sshJumpHost` representation.

Quick Connect uses saved connections and ephemeral cached VM inventory only. `TerminalCommandRouter` targets existing Local/SSH/Telnet/Serial surfaces; snippets use one-pass substitution, quoting, preview and explicit execution. Newlines/control characters cannot use silent Insert and force Run confirmation. Remote editor windows hold SSH leases, bounded UTF-8 content and SHA-256 baselines; Save rechecks content and uses SFTP atomic publish when supported. The final check/publish interval is not a lock; replacement ownership/ACLs are not preserved. Unsaved edits guard editor close and app quit. See [WORKFLOWS.md](WORKFLOWS.md). No new dependency or remote service was added.

## Delivery status (foundation)

Roadmap 21–23 adds `SharedLibraries` allowlisted network metadata, private UUID mappings/baselines and three-way field reviews; reviewed new revisions preserve shared identity but never overwrite another file. Endpoint changes create new credential-free clients instead of redirecting personal secrets. Group moves freeze existing opt-in defaults. `ExternalCredentials` stores provider references separately from profile/connection archives, uses bounded/cancellable private-pipe 1Password reads or ephemeral strict HTTPS KV v2 reads, and keeps Vault tokens in memory. Session password reads are asynchronous; lock epochs and configuration/cancellation checks reject late results.

`PrivacyLock` uses LocalAuthentication device-owner authentication, a synchronous thread-safe credential gate, persisted lock state, first-frame SwiftUI concealment and native AppKit sibling shields for all windows. Locking closes retained tab lifetimes, stops recording/forwards, cancels editor operations, clears temporary logins/provider requests, and closes owned OpenSSH masters off the main thread while retaining the control directory for subsequent use. Unlock does not reconnect/replay; it waits for shutdown and rejects stale/cancelled authentication. This is UI/credential privacy, not encrypted application memory or clipboard erasure. Detailed setup and acceptance limits: [SHARING_PRIVACY.md](SHARING_PRIVACY.md).

Roadmap 15–20 uses `TerminalCommandRouter` source generations/readiness checks for confirmed one-shot multi-target input, `TerminalExperience` weak native registrations for bounded snapshot search and off-by-default recording, and a streaming label/control-sequence filter plus bounded worker-queue log writes. Log files/directories use 0600/0700 and per-profile paths; restarts/close stop recording. `LibraryTools` stores metadata-only terminal profiles/templates/group rules; optional connection fields preserve legacy decoding. Parent-to-child defaults resolve only for explicitly inherited fields before opening a tab. Bulk edits validate all selected records before one connection-store write and never touch Keychain. `MigrationImport` parses allowlisted SSH/RDP/CSV/XML data on a background worker, rejecting unsafe fields/entities and ignoring password data; its UI previews selection/duplicates before adding new UUIDs. Native rebuilds also check their libraries/tools and Xcode first. Scanners/CI reuse the same checker, including tag-only and transitive packages. See [DEPENDENCY_UPDATES.md](DEPENDENCY_UPDATES.md).
