# Reliability and daily-use hardening

These changes are included in the [0.13.0/build 30 preview](releases/0.13.0.md). Automated tests do not certify untested servers or devices.

## What changed

1. **Regression coverage:** local system SFTP-server integration tests exercise listings, literal filenames, pipelined file transfers, recursive folders, conflict policies, cancellation, rename/delete, and malformed responses. Additional checks cover authentication classification, focus activation, recovery state, transfer retry decisions, and large inventory work. Existing RDP sizing, clipboard argument, credential, VNC/WebMKS input, TLS, and lifecycle checks remain in the suite.
2. **Responsiveness:** file I/O and protocol parsing run on serial background workers. Directory browsing reuses a persistent binary subsystem; transfer queues have separate channels from directory navigation. File data uses eight outstanding 32 KiB requests, with bounded buffering and progress updates limited to approximately ten per second. SSH/Telnet prompt detection decodes only a bounded output tail. VM inventory parsing/sorting and debounced search filtering run off the UI thread.
3. **Recovery:** one application-wide observer tracks sleep/wake and network availability/interface changes. It suspends network sessions and file operations, then debounces recovery for two seconds. **Settings → Sessions → Reconnect interrupted network sessions…** is off by default. When enabled, only sessions interrupted by the observer reconnect; explicit disconnects remain disconnected. Local shells and Serial are not restarted by network recovery. Commands, VM operations, and interrupted transfers are never automatically replayed. A host operation already accepted can continue on the host despite a local disconnect.
4. **Connection Check:** available from File, connection context menus, and session toolbars. DNS and TCP checks have five-second limits. HTTPS API checks use strict system trust, no credentials, no redirects, and ephemeral storage. RDP/VNC/SPICE identity negotiation is not falsely reported as checked by a raw TCP probe. Optional **Check SSH/SFTP Login** explicitly reads the selected credential and performs a read-only home listing. The redacted report contains fixed stages/results, never endpoints, account names, server response bodies, paths, certificate values, or tickets.
5. **Transfer queue:** SSH trees and SFTP tabs display queued/running/completed/failed/interrupted jobs, per-current-file byte progress and speed, Cancel, Retry, and destination-conflict resolution. Default behavior asks before overwriting. Resolve with Skip, automatic Rename, or explicit Overwrite/merge. Queues are in memory and not persisted or restored across application launches. Closing their tab cancels their work.
6. **Structured SFTP:** Swift speaks bounded SFTP v3 packets to `/usr/bin/ssh -T -s … sftp`. macOS OpenSSH still owns SSH encryption, configuration, keys, agent, jump hosts, authentication, and host verification. Expect authenticates a command-free `/usr/bin/ssh -T -N -f` master in the app's private control directory; recent OpenSSH `sftp` clients disable master creation, so they cannot seed this transport. Local/remote startup commands, X11 and inherited forwards are disabled for this bootstrap. No user file-operation commands or human-readable directory listings pass through expect. Password bytes remain in the private input pipe, never arguments/environment values. There is no insecure shell/SCP fallback.
7. **Session controls:** SSH, Telnet, Serial, RDP, VM console, and inventory surfaces expose disconnect/reconnect or refresh controls. Local Terminal offers Disconnect/Restart. RDP and VNC/SPICE/VMware consoles expose Fit Screen. Native surfaces request focus on tab activation rather than every redraw; background RDP/Serial connection events do not steal focus. Old terminal-generation callbacks cannot mark a replacement session ended.
8. **Compatibility workflow:** GitHub Actions is configured for macOS 14, 15, and 26 tests/Release builds with retained synthetic test results. A sanitized manual acceptance worksheet complements automated coverage. The matrix has not run until these changes are pushed; real server and hardware interoperability remains separately tracked in `COMPATIBILITY.md`.

## Transfer safety and limits

- Only regular files and directories are transferred. Symbolic links and special files are deliberately not followed in either direction. Remote child names must be valid single path components; control characters, traversal names, oversized packets, unsupported attributes, and unexpected request IDs are rejected.
- A regular upload uses a uniquely named, exclusive `.nethriva-<UUID>.partial` file, then publishes it by rename. Replacing an existing remote file requires the server's `posix-rename@openssh.com` extension. Without that capability, choose Rename; the existing file is not deleted first.
- Downloads stage a private file beside the selected destination and publish only after complete transfer. If the remote size/modification time changes during the download, the previous destination is retained and the job fails for explicit retry.
- Folder transfers/merges are not transactions. Completed children or newly created folders may remain after cancellation/failure. An interrupted remote upload may leave a private hidden `.partial` file when the channel is unavailable for cleanup; inspect/remove that particular file manually if needed. Local partial downloads are removed on failure.
- Retry restarts a job, not a byte-range resume. Rename preserves the existing destination. Overwrite/merge is an explicit decision; it is not a default.
- Each upload attempt reads fresh local size/modification metadata, including its pre-publish check. Reusing a queued URL does not reuse an earlier attempt's cached file metadata; detected source changes retain the previous remote destination.
- File staging is private (0600). Uploads preserve ordinary source permission bits, not setuid/setgid flags; downloads preserve ordinary remote permission bits. Directory creation uses platform/server defaults. Ownership, ACLs, extended attributes, and timestamps are not promised.
- Eight in-flight requests and 32 KiB chunks improve latency tolerance, but no universal speed guarantee is made. Directory responses are bounded to 100,000 entries, 10,000 pages, and 1 MiB per packet; recursive transfers are limited to 64 levels.
- OpenSSH multiplexing may reuse an already authenticated session for the same host/account. A successful check therefore does not prove a newly changed password is correct or validate authentication methods not exercised by that session.

## Suggested local acceptance pass

Use disposable accounts and synthetic files, not valuable production data:

1. SSH: key/agent and password login, unknown host-key refusal in SFTP, rejected password, command input, switching tabs, and explicit disconnect/reconnect.
2. SFTP: expand a large folder while typing in SSH; upload/download nested folders and names with spaces/quotes/wildcards; test conflict choices, Cancel, Retry, and failed transfers without destination truncation.
3. Recovery: enable the setting, sleep/wake, disconnect/reconnect Wi-Fi, and change VPN/interface. Verify manually disconnected tabs remain stopped and transfer/VM operations require explicit retry. Disable the setting and repeat with manual reconnect.
4. RDP: type/edit a filename, secondary click menus, clipboard text, Finder files, window/sidebar resizing, Fit Screen, reconnect, and keyboard focus while switching to other protocols.
5. VM console: framebuffer visible, proportional Fit Screen, pointer alignment, Ctrl+Alt+Del, view-only behavior, clipboard opt-in, disconnect, and a newly requested ticket after reconnect.
6. Telnet/Serial: input/paste/resize, disconnect/reconnect, adapter removal, and no background focus capture. Telnet remains plaintext.
7. Connection Check: unreachable service, unresolvable name, self-signed HTTPS rejection, cancellation, optional SSH login, and a copied/exported report that omits personal details.

Record only app/build, macOS/architecture, sanitized server/product versions, scenario, pass/fail/not-tested, and safe error code. Never add actual addresses, account names, credentials, tickets, raw logs, exports, or infrastructure screenshots.
