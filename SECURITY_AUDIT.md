# Nethriva security assessment

Assessment dates: November 8–11, 2026. Assessed baseline: **0.13.0/build 29**, including extensive pre-existing feature work; operational follow-ups are included in the build-30 preview. This published engineering record documents the assessment scope and unresolved acceptance. Preview availability does not turn the assessment into production security certification.

**Decision at this checkpoint: not ready for a security-approved release.** Local source/native remediations and final integrated checks passed. Production signing/notarization, remote security automation, complete current advisory details and broader native-fuzz acceptance remain incomplete. Do not interpret a passing unit test or an upgraded version string as a complete security assessment.

## Verification checkpoint

Publication analysis follow-up (build 30): remote CodeQL executed successfully on the compatible Intel analysis host and reported [open alert 1](https://github.com/vitalii-sharapov/Nethriva/security/code-scanning/1), `swift/weak-sensitive-data-hashing` (High), in the legacy VMware SHA-1 certificate fingerprint path. SHA-256/full-certificate identities are preferred, but a ticket containing only a legacy SHA-1 thumbprint can still authorize its console certificate. This is certificate identity comparison, not password hashing, and no interception/collision exploit was demonstrated. The weak-hash compatibility path remains in this preview; the alert is not dismissed or declared fixed. Removing its independent trust authority, with legacy interoperability tests, is additional production hardening. The original 15-finding counts below describe the earlier grouped assessment, not this later CodeQL alert. A completed CodeQL job does not mean zero findings.

Remote acceptance also remains incomplete: macOS 26 compatibility jobs pass, but the macOS 27.0.1 virtual machine renders console background instead of the synthetic WebMKS framebuffer. Its failing test remains enabled. The current preview is not promoted to stable/security-approved status; see [the exact execution record](SECURITY_TESTING.md).

## Architecture established from source

Nethriva supports Local Terminal, SSH, SFTP, Telnet, Serial, RDP, host inventory and VNC/SPICE VM consoles. SwiftUI owns management/state; native AppKit views own terminal/desktop input and lifetimes. It is not an SSH server, RDP server, credential-sync service or privileged system daemon.

| Subsystem | Actual implementation and authority |
| --- | --- |
| App/state | `AppState`, `NethrivaApp`, `SessionTab`, session surfaces, detached windows and command router. Sessions retain connection snapshots; saved metadata changes must not retarget a live identity. |
| Persistence | Versioned connection/profile metadata in active-profile UserDefaults stores with recovery backups. Debug, Release and hosted testing use distinct data/credential namespaces. Metadata is not encrypted at rest. |
| Local credentials | `KeychainService`/`GatedCredentialVault`; passwords indexed separately from metadata. Accessibility is `WhenUnlockedThisDeviceOnly`; app privacy gates and epoch checks surround credential operations. |
| External credentials | `ExternalCredentials`: allowlisted 1Password CLI path/reference or strict HTTPS Vault KV v2. Private pipes, bounded responses, redirect refusal, cancellation and volatile tokens; no provider secret copied to connection archives. |
| Terminal | SwiftTerm 1.99.3, pinned revision. Local shell and `/usr/bin/ssh` use real PTYs through app-owned bounded `ManagedProcessTerminalView` delivery. Terminal parser output is untrusted, including on an authenticated SSH session. |
| SSH/SFTP | macOS OpenSSH owns cryptography, host trust, key/agent/config handling and jump hosts. SFTP uses bounded binary v3 framing over a subsystem, independent channels and private authenticated masters. File operations are not shell commands. |
| Telnet/Serial | Network.framework TCP with Telnet negotiation; POSIX no-follow character-terminal I/O with termios for Serial. Neither provides network confidentiality for an exposed legacy path. |
| RDP | Bundled FreeRDP/WinPR/OpenSSL plus Objective-C Cocoa bridge, loaded in-process from app resources. Clipboard, audio, graphics and device channels execute native dependency code. Credentials enter memory/private pipes, not OS argv. |
| Virtualization | VMware SOAP; Proxmox REST, Xen Orchestra RPC/WebSocket, Nutanix REST; libvirt/Hyper-V tools over SSH. Explicit VM power/media/snapshot operations use authenticated account authority and confirmations. |
| Console bridge | Bundled noVNC/SPICE in nonpersistent WKWebView storage. A private scheme serves bundled assets; native-owned descriptors choose TCP/TLS/WSS endpoints, not JavaScript messages. VMware one-time tickets have isolated certificate-pinned/system-trusted channels. |
| Workflows | Snippets, remote text editing, explicitly selected multi-session actions, owned loopback-default tunnels, opt-in output recording and bounded output search. Commands approved by the user intentionally exercise that user's local/remote authority. |
| Updates/releases | Optional publisher-signed manifest/hash/size verification and quarantined download; no automatic install. No publisher key means verified download fails closed. Packaging, native-integrity and production-distribution gates are separate. |

## Untrusted-entry inventory

This table identifies the reviewed input categories and their handlers. It is not a claim that every branch or third-party parser has been exhaustively fuzzed.

| --- | --- |
| Connection/editor/Quick Connect text, sidebar drag/paste | `ConnectionEditorView`, `ConnectionSidebarView`, models and `AppState`: metadata becomes process options, endpoints or credential references. Endpoint/identity changes require credential isolation. Clipboard text is not assumed trustworthy. |
| Plain/encrypted connection archives | `ConnectionTransferService`, import review and `AppState.importConnectionArchive`: untrusted JSON/crypto parameters/UUIDs/capabilities cross into saved metadata and Keychain authority. Bounded regular-file read, schema/ID checks, authenticated decryption and local-only review decisions apply. |
| SSH config/RDP/CSV/XML migration files | `MigrationImport`: bounded text parsing, no Include execution or imported passwords, strict supported fields and review. XML entities/DTD are refused. |
| Shared metadata libraries and changed files | `SharedLibraries`: strict credential-free allowlist, no-follow file access, revision/fingerprint/stale-preview checks, three-way review; changed endpoints become new credential-free records. |
| Local saved stores, backups and profile/provider references | Store services, `LibraryTools`, `ExternalCredentials`: malformed/versioned data is preserved and saving fails closed rather than reset. Only metadata/reference values are persistent. |
| Shell/environment/config/key paths | Local shell startup, `SSHInputValidation`, OpenSSH and provider process launch. Local configuration/environment is user-controlled authority; no shell concatenation of imported file operations. Explicit host/account/jump validation, argument boundaries and fixed helper paths apply. |
| SSH banners, prompts and terminal bytes | PTY surfaces and private authentication helpers: remote text cannot authorize automatic secrets; actual local credential-entry state is checked. Control strings, sixel expansion, OSC52 and links/paste have separate boundaries. |
| SFTP packets, request IDs, directory names/attributes | `StructuredSFTP`: packet/handle/outstanding-response bounds, strict names, aggregate wire/expanded-metadata limits and fixed errors instead of arbitrary server text. |
| Local upload sources and download targets | `SFTPLocalSource`/`SFTPLocalDirectory`, transfer queue/file promises: held descriptors, no-follow children, exclusive staging and atomic publication. Remote filenames never become an unrestricted local path. |
| Remote text edits and changing files | `RemoteFileEditor`/SFTP: regular UTF-8 files up to 2 MiB, fingerprint/change conflicts and explicit overwrite; no distributed locking promise. |
| Telnet commands/options/subnegotiation | Stateful `TelnetProtocolParser` and TCP coordinator; bounded negotiation/terminal ingress. The plaintext warning is retained. |
| Serial paths, bytes and writes | `SerialPortService`: approved device-name shape, no-follow open, `fstat` character-device and `isatty` checks, no root helper and bounded queued input. |
| RDP negotiation/certificates/authentication | `FreeRDPArgumentsBuilder`, private certificate store, `NethrivaRDPBridge` and certificate dialogs: NLA default, TLS minimum, system identity verification and reviewed exceptions. The dependency remains a native malicious-peer attack surface. |
| RDP graphics/audio/cursor/channel/clipboard/file/device input | FreeRDP/WinPR/codecs and Cocoa bridge: dependency upgrades, surface budgets, clipboard focus gates and opt-in redirection. Broad native fuzzing is still outstanding. |
| VM HTTP/RPC/XML/JSON, cookies and authentication responses | `VirtualizationHTTP`, REST/VMware/SSH backends: scoped ephemeral sessions, same-origin redirects or redirect refusal, bounded bodies, XML guards, escaped identifiers and redacted failures. |
| Federation callback and token responses | `VMAdvanced`: native-client PKCE, state/duplicate rejection, strict HTTPS, scoped actively expiring memory authorization and no saved-password fallback. Live IdP certification is not implied by mocks. |
| Console tickets, URLs and TLS certificates | Exact descriptor ownership, endpoint/port-bound pins, system trust fallback only when no supported ticket pin exists, no pin-mismatch downgrade or management-credential forwarding. |
| WK messages, resource URLs, modules and network frames | `VMConsoleAssets`/`VMConsoleWebBridge` and console wrapper: main-frame/custom-origin checks, bounded messages/channels, JSON argument passing, native-selected endpoints, navigation restrictions and no external CDN. |
| Session clipboard/drop/file promises | RDP/console wrappers and Finder integration: explicit feature selection, focus constraints and scoped local file choices; user Copy/Paste is distinct from remote OSC52. |
| Workflow templates/snippet parameters/broadcast targets | `WorkflowTools`, command router, local services: one-pass parameter substitution/quoting, preview/confirmation and explicit targets; privacy lock stops session authority. |
| Recorded output/search/diagnostics | `TerminalExperience` and `DiagnosticReportService`: private bounded explicit logs and filtering; diagnostics omit identifying/secret contents. Recording still cannot guarantee that every remote secret is recognized. |
| Sleep/network events, cancellation, detach/dock/reconnect | Privacy/session recovery/lifetime controllers: generation/epoch checks and owned transport teardown; no silent command/transfer/VM-action replay. |
| Update API/manifests/assets and chosen save path | `VerifiedUpdates`: allowed HTTPS origins, Ed25519 manifest, exact version/architecture/hash/size, no-follow exclusive write and quarantine. Signature trust is independent of Apple notarization. |
| Dependency source archives/build tools and bundled code | Native/Swift locks, checksum verification, safe private staging, SBOM/provenance, Mach-O dependency/signature checks. Upstream source compromise remains a separate trust problem. |
| GitHub PRs, workflow actions and release tooling | Read-only default permissions, commit-pinned actions, no `pull_request_target` execution or publication path in security jobs; PR code remains untrusted and must receive no signing/publishing secrets. |
| Website/download path | Official website/GitHub release links are a distribution trust boundary. Website ownership is separate; no website/infrastructure deployment was authorized. This audit does not certify a compromised site/CDN/account scenario as prevented by app checks. |

## Threat model

Assets include credentials/provider tokens, SSH agent operations, clipboard contents, local files, authenticated remote sessions, administrator authority, VM operations and authenticity of distributed software. Secrets stored safely in Keychain can still be misused if an attacker changes the destination or reaches an authorized credential-send path.

| Attacker capability | Potential damage | Required boundary |
| --- | --- | --- |
| Controls a server to which the user connects | Credential/clipboard theft, hostile parser data, client crash, redirected file access or misleading prompts | Authenticated encryption verifies the endpoint, not the honesty of an already compromised endpoint. Limit authority, isolate sessions and validate every server-controlled input. |
| Supplies a library/migration/shared file | Retargeted credentials, hidden local capabilities, resource exhaustion or unsafe local writes | Import must not create authority from UUIDs or silently authorize security settings. Local review decisions cannot be serialized in the file. |
| Passively observes a network path | Reads legacy plaintext data; sees endpoints, timing and some early metadata | Use verified SSH/TLS on every exposed leg; Telnet/raw TCP remain explicit exceptions. |
| Actively intercepts DNS/routing/TLS/SSH | Endpoint impersonation, protocol downgrade, authentication interception | Reject wrong/changed identity and weaker negotiation; verify first contact deliberately. TOFU alone cannot authenticate an attacker-controlled first encounter. |
| Another local unprivileged process | Predictable-path/symlink/FIFO/socket races or file replacement | Private unpredictable directories, ownership/inode checks, no-follow descriptors and atomic namespace operations. Same-UID arbitrary-code execution is not solved by these checks. |
| Supplies terminal/clipboard/file data | Silent clipboard access, dangerous paste or application-link activation | Separate output parsing from deliberate local user actions; block OSC52, bound parsing and require review for active input/links. |
| Controls a dependency/distribution/workflow input | Executes code on developer/users/CI or substitutes software | Pins, independent review, minimal CI privileges, provenance, publisher identity and production signing/notarization. A checksum alone does not establish publisher identity. |

No production systems were attacked, and no real credentials or user trust stores were used for the reproductions. Tests used generated keys/certificates, synthetic endpoints and in-memory/private disposable fixtures. Same-user malware, root compromise, a malicious OS/password-manager installation and physical attacks require separate controls and are not claimed solved.

## Finding register

“Implemented” means source remediation exists. “Verified” requires the final tests and exact bundled binaries in [SECURITY_TESTING.md](SECURITY_TESTING.md); it never means that the old public/test build was patched in place. The six High/eight Medium/one Low grouping avoids counting every related branch as a separate vulnerability.

### Upstream advisory applicability

[GHSA-jq25-3374-4262](https://github.com/FreeRDP/FreeRDP/security/advisories/GHSA-jq25-3374-4262) covers certificate identity checks through 3.32.1, fixed in 3.32.2; its interception model needs a certificate chaining to a trusted CA. [GHSA-rrp5-666j-g6gp](https://github.com/FreeRDP/FreeRDP/security/advisories/GHSA-rrp5-666j-g6gp) covers dynamic-channel allocation through 3.32.1, fixed in 3.32.2, after channel negotiation. Both include the original bundled version; no live weaponized peer was run.

[OpenSSL's 3.6 advisory record](https://openssl-library.org/news/vulnerabilities-3.6/) includes CVE-2026-35189, a Low-severity certificate-processing allocation issue affecting 3.6.0 before 3.6.5. The current 4.1.0 line is used by the target rebuild; exact-library reachability was not established for every OpenSSL advisory. OSV output does not substitute for that assessment.

The 32-bit overwrite claim in [GHSA-f53w-3364-jr35](https://github.com/FreeRDP/FreeRDP/security/advisories/GHSA-f53w-3364-jr35) is not a demonstrated 32-bit overwrite in this arm64 app. [GHSA-q9p9-j22r-577p](https://github.com/FreeRDP/FreeRDP/security/advisories/GHSA-q9p9-j22r-577p) concerns software smart-card certificate/key logon, not ordinary RDP or ordinary hardware smart-card redirection. Enabled features/build flags must be checked before declaring any advisory reachable.


The [3.33.1 release](https://github.com/FreeRDP/FreeRDP/releases/tag/3.33.1) additionally links eleven advisories: GHSA-23fv-6wrf-5hfq, GHSA-3664-pr8r-3254, GHSA-52rf-pppx-qm55, GHSA-76c4-7552-ffhv, GHSA-9c9j-2r7q-5gx2, GHSA-ch3p-5r9r-w86p, GHSA-f6v9-vx5q-vjpf, GHSA-m33m-4qxh-hq76, GHSA-m6hp-4798-x78x, GHSA-rp99-f9qv-c446 and GHSA-x863-43r4-f7c2. Their global public advisory API endpoints returned 404 on November 11; three linked web pages also returned 404. The release alone does not establish each issue's affected range, enabled-feature reachability or fixed version. That review is explicitly outstanding under NETH-05; do not infer a new confirmed vulnerability in 3.33.1 or declare it vulnerability-free.

## Additional preventive hardening

These measures are not counted as additional proven vulnerabilities: immutable transport snapshots; guarded clipboard/focus handling; terminal URL and dangerous-paste review; bounded Serial writes and descriptor type checks; private regular-file archive reads/atomic writes; standard CommonCrypto PBKDF2 with stronger new-export defaults and legacy authenticated decryption; scoped API/federation redirect and callback guards; no-follow update/log writes; runtime source locks/SBOM; pinned CI actions/scanners and strict distribution verification. They reduce attack paths without claiming every related parser is certified.

## Residual risk and unresolved acceptance

1. Obtain the current release-linked advisory details and finish applicability review (NETH-05). Binary promotion, exact-bundle integrity and final app/native regressions are complete; full malicious-peer coverage is not.
2. Developer ID signing, Hardened Runtime, approved publisher/team identity, notarization and stapled ticket acceptance are required for production. No such distributable was produced. Ad-hoc test artifacts are not production acceptance.
3. A publisher update key is not configured in the inspected build; verified downloads remain disabled rather than trusting unsigned assets. Signing/attestation secrets must stay outside the repository and untrusted PR jobs.
4. Clang analyzed all eight local bridge Objective-C translation units: five ownership diagnostics corrected; 13 dead-store diagnostics remain (not established security findings). Upstream native libraries were not comprehensively statically analyzed. CodeQL is configured for Swift and was not run remotely. Remote workflow execution and branch/release-required-check enforcement have not been established.
5. OSV coverage is limited to indexed Swift-package URLs in the inspected run. Native purls were partly unscannable/misclassified as GitHub Actions. No native “clean scan” conclusion is valid; manually assess upstream release advisories. The fresh version-build monitor checks all 26 managed components, including native tools, direct/transitive Swift packages, consoles, scanners and CI actions, plus Xcode. Official feeds/public refs handle API throttling. This still does not scan all native CVEs.
6. Bounded GFX sanitizer checks and deterministic Swift corpora are not broad protocol fuzzing. LLVM libFuzzer was unavailable in the installed toolchain; a separate broader native-fuzz subtask was also stopped by an automated safety check. Full RDP/audio/clipboard/device/codec campaigns remain untested; ordinary builds, static analysis and bounded unit regressions continued.
7. No live production/server testing, cross-chip certification, M2 RDP acceptance, Intel native RDP, full provider/IdP matrix, physical Serial/USB/smart-card/printer/microphone acceptance or clean-machine notarized launch was performed.
8. Telnet, direct raw TCP consoles, ignored certificates and explicit legacy RDP are residual compatibility choices. They must remain clearly labeled, deliberate and scoped; they do not promise confidentiality or verified identity. SSH forwarding protects its own leg, not an unencrypted final network hop.
9. App Sandbox is not enabled. Current shell/PTY, OpenSSH/config/agent, device and user-filesystem integration relies on capabilities not equivalent to a sandboxed document app. No root helper is introduced; production signing, private storage, explicit input authority and tight parsers compensate but do not equal sandbox isolation.
10. Privacy lock is not full memory encryption, clipboard erasure or defense against same-UID arbitrary-code execution. Recording is explicit and private but may still capture sensitive remote output. Plain metadata archives disclose their documented names/usernames/endpoints and must be treated as sensitive.
11. Website/cloud configuration was not modified or penetration-tested. Independently validate the official site's release links, publisher identity and compromise response before distribution-path acceptance.

No confirmed Critical finding or full arbitrary-code-execution exploit was established. That statement is a scope/evidence limit, not proof of absence. Preserve the original personal library, Keychain, known_hosts and certificate records during remediation; deleting them or disabling validation is not a security fix.

## Dependency-update follow-up — November 11, 2026

The full managed stack is current at the recorded upstream check: SwiftTerm 1.99.3, noVNC 1.7.0, SPICE 85262d0, OpenSSL 4.1.0, FDK-AAC 3.0.0 and CMake 4.4.5; Xcode 27.2 installed from Apple. The coherent native bundle was rebuilt end-to-end under SDK 27.2, with actual binary/provider/provenance verification. New transitive Swift packages are pinned and checked. Eleven gate regressions include real API-throttle fallback design, failure closure and consumed-receipt refusal. The app suites include actual PTY input, guarded output and 2 MiB backpressure checks, plus all prior security regressions. Up-to-date components are not a claim of complete vulnerability absence or production distribution acceptance.
