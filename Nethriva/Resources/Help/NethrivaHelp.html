Nethriva Help

A complete offline guide to organizing connections, using local, SSH, Telnet, and Serial terminals, transferring files, and working with embedded Windows desktops and VM consoles.

Quick start

0.13.0 preview, build 30. Apple-silicon download, macOS 14 or newer. Locally signed and not Apple-notarized; review the GitHub release notes and back up your connection library before testing. Existing saved settings remain in place. Other chips, older OS releases and individual server/device integrations still need acceptance testing.
  1. Choose Add → New Connection in the sidebar.
  2. Select SSH, Telnet, Serial, RDP, Virtualization Host, VNC Console, or SPICE Console. Network connections use a host and port; Serial uses a local device path and line settings.
  3. Choose a group and favorite status, configure any protocol-specific options, and click Add.
  4. Double-click the connection, select it and press ⌘O, or choose Open from its context menu.
  5. For SSH file management, use the tree beside the terminal or choose Open SFTP Browser.
No service account is required. Connections and groups remain on this Mac, and saved passwords are stored in macOS Keychain.

The workspace

Connection sidebar

Favorites, groups, saved SSH, Telnet, Serial, and RDP connections, the built-in Local Terminal, and connection actions.

Session tabs

Independent local terminal, SSH, Telnet, Serial, SFTP, and RDP sessions that remain active while you switch tabs.

Session area

The active terminal, file browser, or embedded Windows desktop automatically fills the available workspace.

Resizable layout

Resize or hide the sidebar. RDP sessions recalculate their remote desktop size to match the visible area.

Closing a tab ends or releases the session it owns. Deleting a saved connection closes every tab associated with that connection. Multiple tabs may be opened from the same saved connection.

Split sessions and SSH workflow tools

Split panes and detached windows

Right-click a tab for Show beside current session, Stack below current session, or Detach to Window. Drag the wide divider handles to adjust adjacent pane sizes; double-click a handle or choose Equal Pane Sizes to balance the group. The existing live surfaces stay connected.

For three or four SSH terminals, open another SSH session, right-click its tab and choose Add to SSH Split. New RDP, SFTP, local terminal and other sessions open alone. New SSH sessions also open alone until you add them. Select any split member's tab to return to that group with its sizes preserved. Remove from Split takes one session out without closing it; Single Pane on a member dissolves the group. Closing or detaching one member preserves the remaining panes. Split layouts are kept for the current app session.

Closing a detached window returns it to the workspace as a single session; its tab close button ends the session. Clicking a pane selects its keyboard target. SSH file trees hide in split mode; use a dedicated SFTP tab beside a terminal.

Quick Connect

Press Command-K to search connection names, host/IP, port and groups, cached VM names/node/host names, or workflow actions. Arrow keys and Return open the selected result. VM results require an inventory loaded during this run; there is no background host scanning or automatic power action. Endpoint visibility follows privacy settings.

SSH Tunnels and jump chains

Choose File → SSH Tunnels, save a local, remote or SOCKS definition, authenticate its SSH tab, then explicitly Start/Stop it. Listeners use loopback ports 1024–65535; server forwarding and GatewayPorts policies still apply. A successful start is not a destination health check. Active tunnels keep their SSH master alive after its last terminal closes; quitting closes it. Lost/interrupted acknowledgements show uncertain state; explicitly Stop before retrying. No forwards restart automatically.

App-owned SSH masters suppress forwarding rules inherited from SSH config; define them in this manager. Keys, agent, aliases, trust and jump settings still apply. Use Configure Jump Chain in an SSH editor to add/reorder up to eight hops. Saved hosts add addresses, not their passwords/key settings. Per-hop authentication follows SSH config/agent; no agent forwarding is silently enabled.

Remote text editing

Right-click a regular file in SSH/SFTP and select Edit Remote File. UTF-8 files up to 2 MiB are supported; binary/NUL data, links and special files are refused. Save (Command-S) re-reads and hashes remote content and stops on a conflict. Reload with confirmation or explicitly choose Overwrite Changed File. Safe replacement needs the server's POSIX rename extension; the old file is never deleted first. Ordinary permissions are preserved, not ownership/ACLs. A concurrent writer can still change content during the final check-to-save interval. There is no autosave or automatic retry; close/quit protects unsaved edits.

Command Snippets

Choose File → Command Snippets for named/grouped templates. Use unquoted {{parameter}} placeholders, fill their values, preview, and choose an open Local/SSH/Telnet/Serial terminal. Shell quoting and execution confirmation default on. Insert sends a single line without Return; Run appends Return. Newlines/control characters refuse silent insertion and require execution confirmation. Device CLIs may need quoting disabled; review the preview carefully. Closed or detected credential-waiting targets refuse insertion; this is not a reliable shell-state detector.

Never store passwords/tokens in snippets. Snippet/tunnel definitions persist locally in the active data profile and are not yet included in connection-library exports. File contents, commands and credentials are not automatically added to diagnostics. All workflow changes require deliberate user actions and are not replayed after reconnect.

Terminal and library tools

Multi-Session Command

File → Multi-Session Command selects individual Local/SSH/Telnet/Serial tabs, none automatically. Enter one line, inspect each real prompt, acknowledge the recipients, then review the exact command/numbered list and choose Execute Once. Closed/restarted/disconnected or detected authentication targets fail preflight; control characters are refused. Input-channel acceptance is not proof of execution. This is not keyboard broadcasting, reliable shell-state detection or an atomic host transaction. No automatic resend occurs. Never put credentials in commands.

Terminal profiles and Find Output

File → Terminal Profiles & Templates manages fonts (9–32 pt), themes, cursors and 100–10,000 scrollback lines. Choose a profile in a client editor or set an app default; appearance applies when a terminal is created/restarted. Find Output searches a read-only in-memory scrollback snapshot (up to 2 MiB/500 result lines). Refresh includes new output; full-screen programs can overwrite it. This is not persistent shell-command history.

Record Output

Recording is always off until explicitly confirmed per terminal. A red Recording output indicator and Stop Recording control remain visible. Only future received output is captured, not keyboard input directly, but a shell/device can echo commands or secrets. Filtering removes terminal sequences and omits sensitive-label/oversized lines; it cannot guarantee secrecy. Avoid authentication/credential-printing commands while recording and review before sharing. Files use random names and private 0600/0700 permissions, a separate Debug/Release profile folder, off-UI-thread bounded writes and an 8 MiB per-log limit. Incomplete final lines are omitted. Stop, disconnect, restart, close and quit end recording; it never resumes automatically.

Retention defaults to seven days, configurable from 1–90 in Terminal Profiles. Starting recording or Settings → Remove Expired Logs permanently removes expired app-owned regular logs, not active logs/symlinks/unrelated files. Show Private Log Folder opens the local folder. Logs are not encrypted by Nethriva and are never part of diagnostics, connection archives or release bundles.

Templates, inherited group defaults and bulk edits

Detected credential prompts stop output recording and require explicit restart afterward; unknown prompts are not guaranteed to be detected. Log warnings remain visible in terminal controls. Expired-log cleanup asks for confirmation in Settings and is disclosed when recording starts.

The tools window manages named protocol templates and group defaults for credential-profile references, ports, SSH jump/keepalive, RDP gateway/scale and terminal profiles. Templates have no passwords/endpoints: Apply Template confirms copying applicable values into an editor draft, still requiring Save. Existing clients do not inherit automatically. Check individual Inherit Selected Fields from Group fields to use the nearest subgroup or parent defaults; unchecked fields retain individual values. Missing rules fall back to the client. Changed defaults apply to new tabs; existing tabs/reconnects keep snapshots. Rename/move follows the subtree; removing a group materializes clients’ settings before moving them to Ungrouped.

Command/Shift-select sidebar clients, right-click and choose Bulk Edit Selected, or use the File menu. Check fields, fill values, inspect before/after previews, then apply one metadata update. Unsupported protocols/unchecked fields stay unchanged. Blank ports/profile selections are skipped; blank jump/gateway clears them. Changed fields stop inheriting. Individual passwords are not read/changed/deleted, and live sessions stay unchanged. Templates/group rules remain local; exports materialize effective values and embed appearance rather than exporting those catalogs.

Migration imports

File → Import Other Formats previews OpenSSH config, RDP files, CSV and unencrypted attribute-based connection-tree XML. UTF-8/BOM UTF-16, 4 MiB and 10,000-record bounds apply. No hosts are contacted or configuration code executed. Password fields/blobs are ignored; existing records are never overwritten. Same-name/endpoint duplicates are unchecked initially; explicitly selecting one adds a separate client. Confirm before saving, including empty XML groups.

SSH imports explicit Host entries with HostName/User/Port/IdentityFile/ProxyJump/ForwardAgent/Compression/ServerAliveInterval; wildcard/Match/Include/command/forwarding directives are not evaluated. RDP imports endpoint/account/domain/gateway and selected display/clipboard/reconnect options, never automatic programs/authentication exceptions/device redirects; certificate checking defaults strict. CSV requires protocol,host, with optional name,port,username,group,domain,gateway,favorite; protocols are ssh/telnet/rdp/vnc. XML accepts Connections/ConnectionTree roots, nested Container Nodes/Groups and Connection Nodes using Name/Protocol/Hostname or Host/Port/Username/Domain. Passwords/inheritance flags/unsupported properties are ignored, and fully encrypted files, DTDs/entities/control-character fields are rejected. These are documented subsets, not complete third-party evaluators; review every preview.

Connections and groups

Sidebar actions

  • Single-click selects a connection or folder; double-click opens a connection.
  • Command-click toggles individual connections or folders. Shift-click selects the visible range between two connections or two folders.
  • Drag a selected row onto a group header or a connection in that group to move all selected items together. A dragged folder keeps its clients and subfolders, including empty ones.
  • Drop connections onto Favorites to favorite them, or onto Ungrouped to remove their group assignment. Drop a folder onto Ungrouped to make it a top-level folder. Moving a connection to a group removes its Favorite marker so it appears there.
  • A folder cannot be moved into itself or onto a destination with the same folder name. Folders cannot be dropped onto Favorites.
  • Groups and connections remain alphabetically sorted; dragging changes group membership, not the manual order within a group.
  • The Add menu creates a connection or a persistent empty group.
  • Right-click a group or use its ellipsis menu to add a connection or subgroup, rename the group, expand or collapse it, copy its path, or remove it. Removing a group also removes its subgroups and moves their connections to Ungrouped; Favorite markers are cleared so all connections appear there, while saved credentials stay unchanged. Renaming updates nested groups and client assignments but not saved credentials.
  • Groups can contain both connections and more subgroups; click the disclosure arrow to expand or collapse them.
  • Type in the sidebar search field, or press Command-F, to find connections by name, hostname or IP address, group path, or port. Multiple words narrow the results.
  • The ellipsis menu applies actions to the selected connection.
  • Right-click a connection to open, quickly rename, edit, duplicate, move, favorite, copy its address, copy an SSH command, open SFTP, or delete it.
  • Removing a group asks for confirmation. Connections inside the group or any nested subgroup are moved to Ungrouped rather than deleted.

Common connection fields

FieldPurpose
NameThe friendly label displayed in the sidebar and tab.
HostA hostname or IP address reachable from this Mac.
PortDefaults to 22 for SSH, 23 for Telnet, and 3389 for RDP. Serial uses a local device path instead of a TCP port.
UsernameThe remote account. RDP also accepts DOMAIN\username.
PasswordOptional secret stored in Keychain. Leaving it blank while editing keeps the existing password; use Remove Saved Password to delete it explicitly.
GroupThe sidebar group containing the connection.
FavoriteShows the connection in the Favorites section.

Duplicating a connection creates a new connection identifier. A connection using its own Keychain password gets a separate copy; a connection linked to a credential profile keeps that same shared link. Deleting a connection does not delete a shared profile.

Import and export

Open the connection-library menu in the toolbar or sidebar, or use the File menu, to import or export your saved library.

  • A normal .nethriva export contains connection settings, groups, credential-profile names, usernames, and domains, but never passwords. Treat even a password-free export as private.
  • Enable Include saved credentials to create a password-protected .nethriva-secure archive containing individual and shared Keychain passwords. The entire archive is encrypted, and its password cannot be recovered.
  • Import shows connection, group, credential-profile, saved-credential, and duplicate counts before changing the current library.
  • For matching identifiers, choose whether to keep existing connections and profiles or replace them. Imported passwords are saved in the active macOS Keychain profile.
Protect credential exports like a password vault. Use a unique, strong archive password and transfer the file through a trusted channel.

Credential profiles

Open Manage Credential Profiles… from the toolbar or File menu. Create a named profile with a username, optional Windows domain, and optional password. The password lives in macOS Keychain; the profile name, username, and domain remain in local app preferences.

  1. Create a profile such as a shared network-admin account or a domain administrator. Enter a new password if you want Nethriva to offer or use it.
  2. In an SSH, Telnet, or RDP connection, choose that profile from the Credentials menu. Its username and password will be used the next time the connection opens; the domain applies to RDP only.
  3. To rotate a shared password, edit the profile once. Every linked connection uses the new password on its next session or reconnect.
  4. To return a connection to its own credentials, choose This connection's own credentials and enter its username/password. Linking a profile removes that connection's old individual saved password.

A profile cannot be deleted while connections still use it. Existing open sessions are not interrupted by profile edits. If an RDP authentication prompt saves new credentials for one linked connection, Nethriva detaches that connection from the shared profile rather than changing the profile for every client.

Settings and privacy

Choose Nethriva → Settings…, press ⌘,, or use the gear button in the main toolbar.

  • Sidebar: show or hide host addresses and usernames below connection names.
  • Sessions: show or hide host addresses and usernames in SSH, Telnet, RDP, and SFTP headers.
  • Recovery: optionally reconnect sessions interrupted by sleep or network/interface changes. Off by default. Explicitly disconnected tabs stay disconnected; terminal commands, VM operations, and interrupted transfers are never replayed automatically.
  • Username display is off by default in both locations. Changes take effect immediately and are saved for the current development or release profile.

These controls affect labels created by Nethriva. A connection name containing a username, or text displayed by a remote system such as a shell prompt, remains visible until changed at its source.

Shared libraries, external credentials and privacy lock

Share network connection structure

Open File → Shared Connection Libraries…, select network clients and review Save New Shared File…. The .nethriva-shared format includes only names, hosts, ports, protocols, groups and VM platform. Usernames, passwords, profile/vault references, SSH keys/jumps, commands and private redirection/trust settings are excluded. Selected clients’ parent groups are included; including all empty groups is a separate opt-in. Local Terminal/Serial are not shared. Files still reveal infrastructure; share only with intended recipients.

Link Shared File… creates independent local client IDs without credentials or inherited rules. Add your personal credentials afterwards. Refresh & Review merges against a baseline: personal-only edits are kept, shared-only edits apply, and conflicting fields keep personal values unless you choose the shared value. Changed destinations require approval and create fresh credential-free clients while keeping former clients independent. Shared deletions keep local clients; personal deletions are not resurrected while linked. Existing tabs are unchanged.

Save New Revision… reviews current linked clients plus any additional selections and saves a new file with the same shared identities. Teammates link the new revision to review its changes. Existing files are never overwritten, and nothing uploads or synchronizes automatically. Unlink removes tracking only. These files differ from ordinary backup/encrypted archives and never contain credentials.

Use a vault without copying its password into Keychain

Save a profile under Manage Credential Profiles…, then enable External credential provider. Link clients through their Credentials picker. New sessions asynchronously request the referenced password; existing sessions retain their current copy.

  • 1Password CLI: install the official op in an offered standard location, enable desktop-app integration and enter op://vault/item/password. 1Password handles authorization; Nethriva does not collect its master password or service-account token. Retrieval uses a fixed command and private bounded stdout pipe, not a shell or credential environment.
  • Vault KV v2: enter an HTTPS server, mount/path, password field and optional namespace. Save the choice, then enter a short-lived token in the secure field and choose Authorize for This App Session. Only the selected KV v2 field is returned. System TLS validation is required; redirects are rejected. Tokens remain in memory and are forgotten on lock/profile change/quit or explicit Forget Authorization. No OIDC login, KV v1 or token renewal is provided.

Test Read (No Password Display) verifies retrieval without displaying or saving the value. External selection overrides an old Keychain password without deleting it. Provider passwords, references and tokens are excluded from all exports. Configure providers separately on each Mac. Bitwarden/other providers are not implemented here; your vault setup and permissions still determine success.

Lock Nethriva

Choose File → Lock & Disconnect Sessions or press ⌘⇧L. All app windows and their accessibility content are concealed, live tabs/recording/tunnels are closed, editor operations are cancelled while unsaved buffers remain hidden, and temporary VM/vault authorization is cleared. Unlock with Touch ID or your Mac login password, not a remote password. Cancelled or failed authentication stays locked, including across app restart. Reopen clients explicitly after unlocking; no commands, transfers or VM actions are replayed.

Settings optionally locks on Mac sleep/screen lock or after 5/15/30/60 minutes without input in Nethriva. Automatic locking is off by default. Remote operations already accepted may continue on the host; verify before retrying. Unlock waits for owned SSH shutdown. If unsaved editor buffers block quitting, unlock to answer the discard confirmation.

This protects the app UI and credential boundary, not files on disk, other same-user processes or encrypted memory. Existing logs/backups and the system clipboard are not erased, and external vault tokens are not revoked at their issuer. Use macOS screen locking/FileVault and vault controls too.

Local Terminal

The built-in Local Terminal launches the current user's configured login shell, falling back to /bin/zsh, and starts in the home directory. It uses a real pseudo-terminal rendered by SwiftTerm.

  • ANSI, xterm, 256-color, and true-color terminal applications are supported.
  • Keyboard input, text selection, copying, and ⌘V paste work directly in the terminal.
  • A secondary-click or two-finger click pastes the clipboard into the terminal.
  • Terminal rows and columns follow the tab size.
  • The shell continues running while another tab is selected and ends when its tab closes.

SSH sessions

SSH sessions use macOS OpenSSH inside an embedded SwiftTerm view. This preserves compatibility with the current user's SSH configuration, host-key database, private keys, and agent.

Authentication modes

ModeBehavior
AutomaticAllows OpenSSH configuration, keys, agent, password, and keyboard-interactive discovery.
Password / InteractiveRestricts authentication to password and keyboard-interactive methods.
Public Key OnlyUses public-key authentication and disables password fallback.

Advanced SSH options

  • Choose a per-connection identity file, including hidden files below ~/.ssh.
  • Connect through an OpenSSH jump host.
  • Enable SSH agent forwarding and transport compression.
  • Configure a keepalive interval from 0 through 3600 seconds.
  • Use a custom SSH port and existing ~/.ssh/config directives.

Host trust and passwords

On first connection, OpenSSH displays the server fingerprint in the terminal. Review it, enter yes, and press Return to add the host to known_hosts. A changed host key is not accepted automatically.

Password characters are invisible by design. Click the terminal, type or paste the password, and press Return. If the connection has a Keychain password, the password banner provides Send Saved Password.

An ended session displays its exit status and offers a reconnect action without requiring the connection to be reopened from the sidebar.

Telnet sessions

Telnet sessions use a native TCP connection and render directly inside a SwiftTerm tab. They are intended for legacy switches, appliances, and other devices that do not provide SSH.

  • Port 23 is selected by default, and any valid custom TCP port can be used.
  • Nethriva negotiates terminal echo, suppress-go-ahead, xterm-compatible terminal type, and window-size updates.
  • Keyboard input, ⌘V paste, secondary-click paste, selection, and terminal resizing work inside the tab.
  • A detected login or username prompt can show Send Saved Username; a detected password prompt can show Send Saved Password. Sending either is an explicit action.
  • An ended or failed session offers a reconnect control.
Telnet is not encrypted. Usernames, passwords, commands, and output can be observed or altered on the network. Use Telnet only on an isolated, trusted management network and prefer SSH whenever possible.

Serial sessions

Connect a USB-to-serial adapter or USB-to-RJ45 console cable that appears as a serial device on this Mac. In Add → New Connection, choose Serial, select an available /dev/cu.* port, and set the line parameters required by the device. The list refreshes while the editor is open; use the refresh button or enter a device path manually if needed.

  • Set baud rate, 7 or 8 data bits, none/even/odd parity, 1 or 2 stop bits, and none/hardware/software flow control. Common console settings are 9600 baud, 8 data bits, no parity, 1 stop bit, and no flow control, but use your device documentation.
  • Enable Local Echo only if typed text is not echoed by the device.
  • Double-click the saved connection to open its SwiftTerm tab. Keyboard input, Command-V paste, selection, and secondary-click paste work there.
  • If the adapter is removed or the port fails, reconnect after it reappears. Close the tab to release the device.
A passive USB-to-Ethernet/RJ45 adapter is not a serial console cable. It must expose a macOS serial device such as /dev/cu.usbserial-… or /dev/cu.usbmodem…. Serial traffic is not encrypted, and Serial connections do not store credentials.

Remote files beside SSH

Every SSH terminal includes a compact remote filesystem tree. Its divider can be resized so the file pane occupies only as much room as needed.

  • Folders load lazily when expanded, avoiding a full recursive scan.
  • Use Parent, Home, Refresh, New Folder, and Upload controls above the tree.
  • Double-click a folder to make it the current tree root.
  • Double-click a file to choose a local download destination.
  • Drop local files or folders on the root or a remote folder to upload them.
  • Drop a remote item on another remote folder to move it.
  • Drag a remote file or folder to Finder to download it.
  • Right-click an item to copy its path or explicitly download it.

The terminal and file operations reuse an authenticated OpenSSH control connection. This avoids repeating a full login for every folder expansion.

SFTP browser

Choose Open SFTP Browser on an SSH connection or press ⌘⇧U while it is selected. SFTP opens in a separate tab and inherits the connection's host, port, username, authentication mode, key, jump host, agent, compression, and saved password.

File operations

The SSH tree and SFTP tab include a Transfers queue with per-current-file byte progress/speed, Cancel, Retry, and conflict resolution. Existing destinations are protected by default: choose Skip, automatic Rename, or explicit Overwrite/merge. Retry restarts a job; it is not byte-range resume. Transfers continue while browsing or switching tabs, but closing the tab cancels them.

File operations use structured SFTP v3 packets over macOS OpenSSH, not textual commands or parsed directory output. Listings reuse a persistent subsystem and transfers use a separate channel. Only regular files and folders are transferred; symbolic links and special files are not followed. Regular files are staged before publication. Safe replacement of an existing remote file needs the OpenSSH POSIX-rename extension; otherwise choose Rename.

Folder merges are not atomic. Completed children and new folders may remain after interruption. A lost connection may also leave a hidden remote .nethriva-…partial file when cleanup is impossible. Inspect/remove that specific partial file manually if needed; the previous regular destination is not truncated by a failed transfer.
  • Navigate to parent and home folders, double-click folders, and refresh listings.
  • View names, sizes, modification values, permissions, links, and file-type icons.
  • Upload multiple files or folders using the picker or drag-and-drop.
  • Upload and download directories recursively.
  • Create folders, rename files and folders, and move remote items.
  • Delete files and empty directories after confirmation.
  • Review item count, endpoint, loading state, and actionable errors in the browser.
Unknown host key? SFTP does not silently accept one. Open an SSH tab, verify and accept the fingerprint, then refresh or reopen SFTP.

Embedded RDP

RDP sessions use the bundled FreeRDP runtime and a native Cocoa view bridge. The Windows desktop stays inside its Nethriva tab—there is no separate remote-desktop window.

Display and performance

  • Dynamic resolution follows the logical tab area, not doubled Retina backing pixels.
  • The remote layout updates when the app, sidebar, or session divider changes size.
  • Choose Comfortable (100%), Larger (140%), or Largest (180%) interface scaling.
  • Modern graphics enables a 32-bit H.264/AVC444 pipeline; disabling it selects software graphics fallback.
  • Network profiles include Automatic, LAN, Fast Broadband, Limited Broadband, WAN, and Very Slow Link.

Authentication, gateway, and reliability

  • Network Level Authentication with username, password, and optional domain.
  • DOMAIN\username is separated into the correct domain and account automatically.
  • If prompted for RDP credentials, optionally select Save credentials in Keychain. Nethriva saves them only after the remote desktop connects; failed or cancelled logins are not saved. The checkbox is off by default and does not apply to gateway or smart-card prompts.
  • Optional Remote Desktop Gateway host and gateway username.
  • Optional administrative session.
  • Automatic reconnection with a configurable retry limit.
  • Certificate policies: Trust on First Use, Require Valid Certificate, or Ignore Certificate Warnings.

Devices and audio

  • Play remote audio on this Mac, leave it on the remote computer, or disable it.
  • Optionally redirect the microphone, home folder, a selected local folder, printers, smart cards, and USB devices.
  • Clipboard redirection is enabled by default and can be disabled per connection.
Certificate warning: Ignore Certificate Warnings disables server-certificate verification and prevents detection of man-in-the-middle substitution. Prefer Trust on First Use or Require Valid Certificate.

RDP pointer, keyboard, clipboard, and files

Pointer and keyboard

  • Primary click, secondary click, dragging, pointer movement, and wheel scrolling are translated to remote coordinates.
  • Two-finger trackpad clicks open the Windows context menu at the remote pointer location.
  • Clicking the embedded desktop restores keyboard focus.
  • ⌘C, ⌘X, ⌘V, and ⌘A map to the corresponding Windows edit shortcuts.

Text and Finder item transfer

  • Unicode text clipboard redirection works in both directions when allowed by the Windows host.
  • Copy Finder files or folders and use the RDP paste action to send them to Windows.
  • Drag Finder files or folders directly over the intended Windows desktop or Explorer destination.
  • Nethriva activates the remote drop point and uses standard RDP file-clipboard streaming rather than making a duplicate local transfer folder.

If transfer is blocked, confirm that Share clipboard is enabled and that Windows Group Policy or the RDP server has not disabled clipboard redirection.

Security and privacy

  • Saved passwords are device-local generic-password items in macOS Keychain, keyed by connection UUID and available only while this Mac is unlocked.
  • Password values are not stored in the connection record and are redacted from application-visible RDP argument logs.
  • SSH host identity is protected by the current user's OpenSSH known_hosts checks.
  • SFTP authentication passwords enter a private pipe, never arguments/environment variables. File requests are binary packets; unsafe path components/control characters and unbounded server responses are rejected.
  • Telnet provides no encryption or host-identity verification and must be treated as a legacy, trusted-network-only protocol.
  • Serial uses a local device and does not encrypt bytes sent over the cable.
  • RDP credentials are supplied to the embedded native client without appearing in a separate RDP process list.
  • Sensitive RDP redirects are disabled unless enabled in that connection's settings.
  • Connection and group records remain in the current macOS user's local preferences.
  • Plain connection exports cannot contain passwords. Credential exports encrypt the complete archive with password-based AES-256-GCM and are saved for current-user access only.
  • Xcode Debug builds use a separate development connection library and Keychain service, so personal Release-profile records do not appear in test builds.
  • Nethriva does not require a hosted account and does not provide cloud synchronization, telemetry, or a hosted relay in this release.

App Sandbox is disabled because Nethriva must launch local shell, SSH, and SFTP processes and access user-selected files. A distributed build still requires appropriate signing, hardened-runtime, notarization, and entitlement review.

Troubleshooting

SSH reports a Unix socket path is too long

Build 30 reserves OpenSSH’s temporary socket suffix within macOS’s limit. Rebuild/relaunch the updated app, then reopen the failed SSH tab. Your saved connection/password can stay unchanged; do not delete socket directories or change the server to work around this app bug.

RDP runtime cannot load in an Xcode build

Use the Nethriva scheme’s Development Run configuration for locally signed native libraries. Strict Release archives require compatible production signing identities. Error details are selectable and scrollable with readable light/dark colors. This local loader error occurs before an RDP login and does not establish a server-password or certificate failure.

macOS keeps asking for my login keychain password
This macOS permission dialog asks for the login keychain password, not the remote server password. Nethriva reads an existing saved credential without rewriting it, and its connection editor checks only whether a password exists. If the password is rejected, open Keychain Access and check whether the login keychain unlocks with your current Mac login password or a previous one. Do not reset the keychain merely to dismiss a prompt; a reset can remove saved passwords. See Apple's keychain-password guidance.
I cannot type or paste into SSH
Click inside the terminal first. Password input is invisible, so type or paste it and press Return even though no characters appear. Command-V pastes; secondary-click also pastes into terminal sessions.
Telnet does not connect or accept keyboard input
Confirm the device exposes Telnet on the configured port and that no firewall blocks it, then click inside the terminal before typing. Use Telnet only on a trusted management network because its traffic is unencrypted.
My serial port is missing or will not open
Confirm that the cable is a USB serial console adapter, not an Ethernet adapter; check that it appears as /dev/cu.* after connecting it. Some adapters require a macOS driver. Reopen or refresh the editor, ensure another terminal app is not using the port, and match your device's baud and framing settings. An unplugged port cannot be opened.
SSH keeps asking whether the host is authentic
Verify the displayed fingerprint, enter yes, and ensure the current user can write to ~/.ssh/known_hosts. Investigate changed-host warnings instead of replacing the key automatically.
The remote file tree is empty or slow
Connect through SSH and approve the host key first. Confirm the server enables SFTP and that the account can list the directory. The first connection performs DNS, trust, and authentication work; later operations reuse its authenticated control connection.
SFTP reports authentication, timeout, or permission errors
Check the connection's authentication mode, identity file, agent, jump host, port, and username. Confirm the server's SFTP subsystem is enabled and the account has permission for the requested path. Use the error action to open the associated SSH session when host trust requires attention.
RDP says logon failed
Windows rejected the supplied account information. Re-enter the password and verify the domain. Use DOMAIN\username or the dedicated Domain field, and confirm the account is allowed to use Remote Desktop with Network Level Authentication.
RDP is too small, too large, or pointer clicks are offset
Resize the Nethriva window once and allow Windows to apply the layout. Use Comfortable, Larger, or Largest interface scaling. The app sends logical tab dimensions and recalculates them when the sidebar changes.
RDP clipboard or file drop does not work
Enable Share clipboard and check the Windows host's clipboard-redirection policy. For files, drop directly over the intended Windows desktop or Explorer view, or copy the items in Finder and choose the paste action.
My connections disappeared in an Xcode Debug build
Debug and Release intentionally use separate connection libraries and Keychain services. This keeps personal records out of development builds. Run the Release configuration to access the existing Release library, export it, then import it into Debug only if you want a development copy.
I cannot open an encrypted connection archive
Confirm that you entered the exact export password. Nethriva cannot recover an archive password. A wrong password or a modified archive is rejected without importing partial data.
An RDP certificate is rejected
Use a certificate trusted by the Mac when Require Valid Certificate is selected. Trust on First Use is appropriate when you can verify the initial certificate. Ignore Certificate Warnings is available for controlled environments but removes certificate-substitution protection.
The help page or package resources are missing
In Xcode choose Product → Clean Build Folder, confirm the Nethriva scheme and My Mac destination, and build again. The help file must appear in the app target's Copy Bundle Resources phase.

Connection Check and recovery

Choose File → Connection Check…, the connection context menu, or its session toolbar button. DNS and TCP probes do not log in. Applicable HTTPS API checks use strict system trust and never follow redirects or bypass self-signed-certificate failures. A TCP success does not prove RDP, console identity, or authentication works.

Check SSH/SFTP Login is optional and explicitly uses the selected credential for a read-only home listing. An existing authenticated OpenSSH master may be reused, so success does not necessarily validate a newly changed password. Copy/export the redacted report to share only fixed stage results, not endpoints, usernames, paths, credentials, certificates, or tickets.

After interruption, use Reconnect/Refresh or opt into automatic session recovery in Settings. Interrupted transfers require manual Retry. RDP and VM consoles offer Fit Screen; local terminals offer Disconnect/Restart. Background tabs do not request keyboard focus on every redraw.

Current limitations

  • The bundled RDP runtime is currently Apple-silicon only.
  • Recursive deletion of non-empty remote SFTP directories is disabled.
  • SFTP does not automatically trust unknown SSH host keys.
  • Telnet has no transport encryption or server-identity verification.
  • Serial sessions require a compatible local adapter and do not provide transport encryption.
  • Connection and group data are local and do not synchronize between Macs.
  • There is no automatic library synchronization, team vault, or credential-sharing service.
  • RDP redirection features depend on the remote host's Windows policy and configuration.
  • A separate stored Remote Desktop Gateway password field is not currently available.
  • Developer ID distribution signing, notarization, automatic updates, and a polished installer remain future deployment work.

Power and guest-tools media

Select a VM and use VM Actions for start, shutdown/reboot, suspend/resume where supported, reset, force-off, and ISO/tools media operations. Disruptive actions ask for confirmation. Host permissions and guest cooperation determine success; inspect the host task log for queued requests.

  • VMware Tools and Nutanix Guest Tools actions ask the host to insert its installer media. Installation happens inside the guest.
  • QEMU/libvirt, Proxmox, Hyper-V, and Xen Orchestra can use an administrator-configured guest-tools ISO/VDI. There is no universal installer for all guests. Modern Windows Hyper-V integration services usually come through Windows Update.
  • ISO references must already exist on the host: a Proxmox volume ID, VMware datastore path, libvirt absolute path, Hyper-V Windows path, Xen Orchestra VDI UUID, or Prism image UUID.
  • An existing CD/DVD drive is required where the host uses one. Nethriva does not overwrite another virtual disk, upload a local ISO automatically, or install guest software itself.
New integration status: Automated checks do not certify every hypervisor or identity provider. Live host testing is still required. Test force-off, reset and snapshots only on disposable VMs. The new registered-client VMware MFA flow requires administrator setup; older Nutanix console APIs remain unsupported.

Details, snapshots and task progress

Select a VM and use Details for available host, guest OS, CPU/RAM, tools and IP information. Missing agent/API data reads Not reported. Guest IP SSH/RDP buttons open separate unsaved connections with no copied host credentials.

The panel offers confirmed Create Snapshot, Revert and Delete for VMware, Proxmox, Hyper-V and stopped libvirt domains. VMware/Proxmox snapshots exclude guest memory and do not request application quiescing; Hyper-V uses its configured checkpoint policy. Snapshots are not backups. Reversion can discard changes and alter power state; deletion removes a recovery point. No forced or recursive-delete flags are used. Xen Orchestra/Nutanix snapshot controls are unavailable in these adapters.

Host task percentages appear when VMware reports them; other supported tasks show indeterminate progress. Stop Monitoring cancels local observation, not an already accepted host operation. Refresh the host to check its state; no request is replayed.

Interactive vCenter federation

Enable Interactive federated sign-in in the VMware connection editor. Your administrator must register a public/native OAuth authorization-code client with S256 PKCE and redirect nethriva-auth://oauth/callback, then supply approved HTTPS authorization/token URLs, client ID, scopes and optional resource. Choose the exchange token type required by that integration. This is not automatic discovery or a password-grant workaround.

Use Federated Sign In in the inventory tab. The system browser handles MFA; vCenter 7.0.2+ exchanges the token for a SAML bearer assertion used with SOAP LoginByToken. System-trusted HTTPS is mandatory. No client secret, MFA bypass, token persistence or automatic refresh is provided. Assertions stay in connection-scoped memory for at most five minutes and are cleared on lock/quit/last-related-tab close/deletion. Holder-of-key tokens are unsupported. Actual provider acceptance remains pending.

VMware console opening uses API-authorized WebMKS tickets, not the vCenter website. If inventory loads with your API credentials, no additional ADFS browser sign-in is needed for the console. The Mac must reach the returned ESXi host and port. Each reconnect obtains a fresh ticket; tickets cannot be reused. The ESXi certificate must match the API-issued identity, or pass system validation when no identity is supplied. Management cookies and HTTP credentials are never forwarded to the console host. Verify the API certificate carefully; do not disable federation or MFA to use this client.

VMware ticket sockets use native TLS/WebSocket networking with TLS 1.2 or newer, without an app-wide transport-security exception. Console failures distinguish a ticket/certificate mismatch, missing identity with system-trust failure, TLS negotiation failure, or a later connection failure. Report only this message, its numeric TLS/network code, and host software versions; never share ticket URLs or credentials. Redirects and extra HTTP logins are not followed. Resolve certificate mismatches in the host/vCenter rather than disabling verification. Tickets that omit the optional hash-algorithm field are supported when their SHA-1 or SHA-256 digest is valid.

An API-supplied WebSocket URL takes precedence over separate host/port metadata, while WSS and certificate verification remain required. Standalone ESXi may omit an already-known endpoint; vCenter's address is never substituted for an unknown ESXi target. Invalid-ticket errors name a fixed field label. Report that label and server versions only, not ticket contents or raw SOAP responses.

If the console reports Connected but is blank, rebuild older 0.13.0 development sources: an unused SPICE container previously pushed the VNC/VMware display below the visible tab. Only the selected renderer now occupies that area. If a current build still shows black, compare the guest in the host's console and check guest screen blanking; do not restart or reconfigure the VM solely to troubleshoot this layout issue.

VM consoles and controls

Use a direct VNC Console or SPICE Console connection for a QEMU console or compatible exposed endpoint without a supported inventory service. Specify the actual port (defaults are 5900 for VNC and 5930 for SPICE). Choose Direct TCP, TLS-wrapped TCP or Secure WebSocket; a WebSocket path looks like /websockify, not a full URL.

Raw TCP consoles are not encrypted. Use a trusted isolated network or select a saved SSH connection for forwarding. The target address is interpreted on the SSH host. WSS validates the configured server certificate; native VNC/SPICE TLS ports are not the same as a WSS proxy.

TLS-wrapped TCP requires a listener that encrypts the entire stream before VNC/SPICE negotiation, such as an approved TLS proxy—not a VeNCrypt-only listener. It requires TLS 1.2+, macOS system certificate trust and matching hostname, never Ignore/TOFU or plaintext fallback. Use the correct port configured by the server administrator.

If a console fails

Check graphics configuration, host console permissions, SSH trust/master availability, console password, firewall, proxy WebSocket support, and guest agent. If only inventory works, console authentication or host API capability may differ. Nutanix WSS needs an accepted bearer token or session cookie; Basic credentials alone are not assumed sufficient. Share sanitized host/guest versions and symptoms when reporting issues, never passwords or console-ticket URLs.

X11, keyboard navigation and updates

In SSH Options → X11 Forwarding, choose Off (default), Untrusted (-X) or Trusted (-Y). Install/start XQuartz separately, then choose Detect XQuartz Display; a fresh install may need logout/login. The remote server needs X11 forwarding and xauth. Trusted mode lets remote apps interact with other X applications or monitor input; use only fully trusted hosts. No public X11 listener or xhost + is needed. X11 terminals use a dedicated non-multiplexed transport; SFTP disables X11 and may require separate authentication.

Sessions menu: ⇧⌘[/⇧⌘] switches sessions, ⌘1–⌘9 selects numbered tabs and ⇧⌘W closes the current session; ⌘W keeps normal window behavior. Detached selection raises its existing window. In the focused sidebar, ↑/↓ selects, Shift+↑/↓ extends selection, ←/→ collapses/expands a group, Return opens/toggles, and typing begins search. Return in VM inventory opens a running guest. Enable macOS Keyboard Navigation to Tab through all controls. Return on a privacy shield starts Mac-authenticated unlocking.

Help → Check for Updates is optional/manual. Downloads require a publisher Ed25519 public key pinned in the build, a signed newer-release manifest and exact ZIP checksum/size. Current source has no publisher key, so verified downloads are disabled; Official Releases remains available. Installation is manual; no Gatekeeper/quarantine bypass occurs. A locally signed, non-notarized app may need System Settings → Privacy & Security → Open Anyway after reviewing its source and checksum.

The application core cross-builds for arm64/Intel, but this repository still includes only arm64 FreeRDP. Universal packaging refuses a missing matching Intel runtime; no Intel RDP release or full VoiceOver certification is implied.
